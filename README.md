# </>SimpleCoder

A lightweight terminal coding and chat client tuned for **local** models (Ollama, 
llama.cpp server, LM Studio, vLLM — anything exposing `/v1/chat/completions`), but 
works against any OpenAI-style endpoint. Responses stream token-by-token, and the 
model can call tools (file operations, shell, web access), skills and MCP servers 
to act on your machine.

It's a hobby project, far from being perfect or as complete as OpenCode or Claude Code;
the goal was to build a simple and fast application in C++ with minimal dependencies
(ncurses, curl, threads and sqlite3) so it will run on any hardware. No *nodejs* 
dependency.

```

│ > summarise src/app/App.cpp and check it builds                            │
```

## Features

- **Streaming chat** token-by-token, so local models feel responsive.
- **Reasoning display** — `reasoning_content` streams into a dimmed block that
  auto-folds to a one-line summary once the answer starts (**Tab** toggles).
- **Tool calling** with a confirmation gate: the model can read/edit files, run
  shell commands, and (opt-in) search and fetch the web. Read-only tools run
  silently; editing/destructive ones prompt for approval — file edits show a
  **colored diff** in the prompt so you approve the actual change.
- **Collapsible tool output** — results show as a one-line summary
  (`▸ read_file ✓ (512 lines)`) you expand with **Tab**.
- **Cancel** an in-flight response mid-stream with **Esc**.
- **Auto-compaction** — when context usage nears the window limit, the
  conversation is summarised automatically to free up room (also manual via
  `/compact`).
- **Generation speed** (tokens/second) shown in the status header.
- **Context-usage gauge** against the server's window (auto-detected or
  configured).
- **`@file` attachments**, **multi-line + UTF-8 input**, **line-level markdown**
  (fenced code, headers, lists), and **scrollback**.
- **Image input** — `@photo.png` attaches an image as an OpenAI `image_url` part
  for vision-capable models.
- **`AGENTS.md`** as an auto-loaded system prompt, generated by `/init`.
- **Skills** — reusable prompt snippets under `./skills`, invoked as
  `/skill <name>` or `/<name>`.
- **MCP servers** — connect to external [Model Context Protocol](https://modelcontextprotocol.io)
  servers (filesystem, git, …) and use their tools as if built in (opt-in via
  `mcp_config`; remote tools require confirmation).

## Requirements (Linux)

System packages:

```sh
# Debian/Ubuntu
sudo apt install build-essential cmake pkg-config \
  libcurl4-openssl-dev libsqlite3-dev libncursesw5-dev catch2
```

`nlohmann/json` is vendored as a single header in `third_party/` — no install
needed. Catch2 v3 is only required to build the test suite.

## Build

```sh
cmake -B build       # re-run after adding source files
cmake --build build  # builds SimpleCoder, the llm_core library, and unit_tests
```

The build uses `-Wall -Wextra -Wpedantic` and is warning-clean.

## Run

```sh
./build/SimpleCoder --version
./build/SimpleCoder --help
./build/SimpleCoder              # interactive chat (needs a configured server)
./build/SimpleCoder my.conf      # use a custom config file
```

Quick ad-hoc run against a local server:

```sh
env OPENAI_BASE_URL=http://localhost:8080/v1 MODEL=<model> ./build/SimpleCoder
```

### Keys

| Key | Action |
|-----|--------|
| Enter | send the message |
| Alt+Enter | insert a newline |
| Esc | cancel the in-flight response |
| Tab | fold/unfold the last reasoning or tool-output block |
| ↑ / ↓ | scroll by line (move the cursor while typing) |
| PgUp / PgDn | scroll by a page |
| Home / End | jump to top / bottom |
| Mouse wheel | scroll |
| F1 | help overlay |

### Slash commands

| Command | Action |
|---------|--------|
| `/help` | show the command/key overlay (also F1) |
| `/clear` | reset the conversation |
| `/retry` | resend the last message |
| `/model [name]` | list the server's models, or switch to one |
| `/compact` | summarise the conversation to free up context |
| `/init` | generate an `AGENTS.md` from the project |
| `/skill [name]` | list skills, or run one (also `/<name>`) |
| `/quit` | exit (also `/exit`) |

Prefix a path with `@` (e.g. `@src/main.cpp`) to inline a file into your message.
An image path (e.g. `@diagram.png`) is sent as an `image_url` content part for
vision-capable models instead of being inlined as text.

## Tools

Exposed to the model via the OpenAI `tools` schema. Read-only tools run without
prompting; editing/destructive tools require confirmation (with an optional
"always allow for this session"), and `write_file` / `str_replace` show a colored
unified diff of the change in the prompt. There is no path sandboxing — the
confirmation prompt is the safety boundary.

| Tool | Gated? | Purpose |
|------|--------|---------|
| `read_file` | no | return a file's contents |
| `list_dir` | no | list a directory |
| `grep_search` | no | regex-search a file or tree |
| `write_file` | yes | create/overwrite a file |
| `str_replace` | yes | surgical edit of a unique substring |
| `make_dir` | yes | create a directory (and parents) |
| `run_bash` | yes | run a shell command |
| `web_search` | opt-in | search a configured backend (SearXNG / Tavily / Brave) |
| `fetch_url` | opt-in | fetch a page and return its readable text |
| *MCP tools* | opt-in, gated | tools served by external MCP servers (see below) |

The web tools are only exposed when `allow_web = true` (see below), since they
make outbound network requests.

### MCP servers

Point `mcp_config` at a sidecar JSON file listing external
[Model Context Protocol](https://modelcontextprotocol.io) servers; their tools
are spawned, discovered (`tools/list`), and exposed to the model alongside the
built-ins. Remote tools always require confirmation, and when more than one
server is configured their names are namespaced `<server>__<tool>`.

```json
{
  "mcpServers": {
    "filesystem": { "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/data"] },
    "git": { "command": "uvx", "args": ["mcp-server-git"] }
  }
}
```

## Test

```sh
ctest --test-dir build
# or run the binary directly, by name or tag:
./build/unit_tests "[skills]"
```

Integration tests (`[integration]`) target an OpenAI-compatible server at
`OPENAI_BASE_URL` (default `http://localhost:8080`) and auto-skip when it is
unreachable, so the suite is green offline.

## Configuration

Config is a simple `key = value` file (`#` comments; values may be quoted, with
`\n` `\t` `\"` `\\` escapes inside quotes). It is read, with later sources
overriding earlier ones, from:

1. `$XDG_CONFIG_HOME/SimpleCoder/config.conf` (default `~/.config/SimpleCoder/config.conf`)
2. `config.conf` next to the binary
3. `./config.conf` in the current directory
4. environment variables `OPENAI_BASE_URL`, `OPENAI_API_KEY`, `MODEL`

`base_url` is the only required field. On first run with no config anywhere, a
commented starter file is written next to the binary. See
[`config.example.conf`](config.example.conf) for the full annotated template.

| Key | Default | Meaning |
|-----|---------|---------|
| `base_url` | — (required) | OpenAI-compatible endpoint, e.g. `http://localhost:8080/v1` |
| `model` | — | model name (many local servers ignore it) |
| `api_key` | — | usually unused locally |
| `temperature` | `0.7` | sampling temperature |
| `context_size` | `0` | context window in tokens; `0` auto-detects from the server |
| `auto_compact` | `true` | auto-summarise when context fills up |
| `auto_compact_threshold` | `0.85` | fraction of the window that triggers it |
| `max_image_bytes` | `10485760` | reject `@image` attachments larger than this (`0` = no limit) |
| `max_tool_iterations` | `50` | max model round-trips in one tool loop before giving up |
| `system_prompt` | — | inline system prompt (`AGENTS.md` takes precedence) |
| `allow_web` | `false` | expose the `web_search` / `fetch_url` tools |
| `search_backend` | `searxng` | `searxng` \| `tavily` \| `brave` |
| `search_url` | — | search backend endpoint |
| `search_api_key` | — | search backend key (Tavily/Brave) |
| `mcp_config` | — | path to a sidecar JSON file of MCP servers (see [MCP servers](#mcp-servers)) |

## Skills

Drop Markdown files under `./skills` (project) or `~/.config/SimpleCoder/skills`
(user) to define reusable prompts. Optional frontmatter sets the name and a
description; without it, the filename is the name. Project skills win over user
skills on a name clash.

```markdown
---
name: review-diff
description: Review the staged git diff for bugs.
---
Run `git diff --staged` and review the changes for correctness bugs,
focusing on edge cases and error handling.
```

Then `/skill` lists what's available and `/review-diff` (or
`/skill review-diff`) injects those instructions into the turn.

## Architecture

All code except `main.cpp` lives in the **`llm_core`** static library, linked by
both the `SimpleCoder` executable and the `unit_tests` binary. Layers, lowest to
highest: `llm/` (protocol — messages, requests, streaming, libcurl client),
`agent/` (tool-calling loop, tools, confirmation gate), `net/` (HTTP for the web
tools), `mcp/` (Model Context Protocol client behind a JSON-RPC transport seam),
`ui/` (ncurses widgets), and `app/` (event loop, config, commands, skills).

Two patterns run throughout: **ncurses is touched only on the main thread** (a
worker thread runs the request and posts events back through a thread-safe
queue), and **pure logic is split from I/O and rendering** so layout, parsing,
key handling, and the tool loop are unit-testable headless. See
[STRUCTURE.md](STRUCTURE.md) for the file-by-file layout.
